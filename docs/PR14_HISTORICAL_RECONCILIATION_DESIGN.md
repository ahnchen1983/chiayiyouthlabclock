# 歷史八月對帳來源：待決設計，不是回補授權

現行正式主檔只能未來生效的保護保留。2026-08對帳不能藉由修改主檔head、回填較早生效日、覆寫已鎖run或啟用正式政策達成。此文件僅提出可覆核的工程邊界；未建立正式資料、未變更保護、未替使用者作出歷史資料授權決策。

## 建議路徑：獨立歷史對帳證據集

另存明確標記為 `historical-reconciliation` 的不可變證據版本，範圍綁定月份與員工，不寫入 `payrollMasterHeads`／`payrollMasterVersions` 的正式採用鏈。每筆保存來源識別、來源日期、記錄者／時間、覆核者／時間及逐項資料缺漏；記錄日與資料所描述的有效期間分開，不偽造當年已核定的歷史事件。

以相同計算引擎作唯讀對帳，但結果清楚標記其來源為事後核實證據集。現有已鎖run始終作為原始不可變基準。證據集的新版本不能改動舊run；D流程只新增對照、原因及經獨立覆核的差異紀錄。人工輸入實發明細是記錄的證據，不等於系統已付款或已確認付款。

提案者、當事員工及任何歷史編輯者不得核定自己的證據集或差異。來源、版本或缺件變動後，既有對帳核定失效，要求新版本重新覆核。原始薪額、實際工作、日別、投保／稅務與實發各自保留來源，不能只填一個net值取得ready。

公開repo只保存schema、合成fixtures與匿名驗證統計；真實證據／附件不進Git或CI。實際建立與使用正式歷史證據集須由授權人員另行決定；本任務只可驗證合成流程。

## 其他選擇與取捨

- **只做外部唯讀對帳報告**：不持久化歷史證據集，可先整理缺件與試算；每次重跑需重新提供完整來源，系統內的D來源重驗與版本追溯較弱。
- **獨立、限縮的遷移程序**：只有在歷史資料採用範圍、核准角色、備份與回復方式明確後才設計；不能把既有future-only規則改成一般可回填，也不能把遷移結果直接當付款授權。

## 仍需一次明確決策

是否採用「獨立歷史對帳證據集」作為八月的系統內對照來源，或只產出外部唯讀報告。這是歷史資料的授權與保留方式，不是重問週起始日、個人日別、實際工時／休息、月中到職折算、單一月薪結構或八月人員範圍；那些決策均沿用既有交接。

在決策前仍可完成共用逐項來源、清冊／支付與免扣證據流程、D比較與核定、異常證據鏈及合成驗證。`PRODUCTION_RECONCILIATION` 不因本文件或合成測試而解除。

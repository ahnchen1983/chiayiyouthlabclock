# 先上線小範圍版本（V1）規劃

日期：2026-10-25。基準：main `84091c6`（8/5 最後上線）、PR13 `13717ca`、PR14 `f5230c1`。本文件是規劃，尚未合併、部署或寫入任何正式資料。

## 一、盤點後的兩個關鍵事實

1. **不能從 main 逐項挑功能上線。** 新功能幾乎都建在 PR13 新增的共用模組上（main 都沒有）：

   | 功能 | 依賴的新模組 |
   |---|---|
   | 補打卡新流程 | monthGuard、clockMutation、makeupEvidence、makeupAttachments、payrollPreflight |
   | 假單撤銷／銷假 | anomalyExplanations、attendanceCaseService、leavePolicy、monthGuard |
   | 加班申請 | attendanceCaseService、monthGuard |
   | 異常案件中心 | attendanceCaseDetector、compLedger、payrollReviewStorage、monthGuard |
   | 例假／休息日指定 | monthGuard、attendanceCaseLifecycle、useAnomalyOperation |

   逐項移植等於重寫一次，風險比整包合併高。好消息是 main 從 8/5 後沒變動，PR13 直接以現行 main 為基準，合併不會有衝突。

2. **整包合併會讓「系統內月結」停擺。** PR13 把計薪改成要先完成每月政策與保費覆核才算 ready，且月結鎖定（lock-month）被固定的 5 項能力缺口硬擋，**合併後任何月份都無法在系統內鎖定月結**；薪資頁會顯示「待覆核」而不是金額。這是刻意的安全設計，但會改變現在的使用方式。

## 二、建議路線：整包合併，但限制上線範圍

選哪條取決於第三節第 1 題（目前八月、九月薪資實際怎麼發）。

| 路線 | 適用情況 | 做法 | 工作量 |
|---|---|---|---|
| **A 試算模式** | 薪資實際是在系統外算（Excel／會計），系統的薪資頁只是參考 | 整包合併。薪資頁與員工「我的薪資」明示「試算中，不作為發薪依據」；月結鎖定暫停。隱藏政策未核前沒有作用的選單 | 小：文案與選單調整＋上線檢查 |
| **B 舊計薪並行** | 每月仍靠系統計算＋鎖定月結來發薪 | 整包合併，另加「舊計薪模式」：正式金額與月結沿用 main 版算法，新引擎只並排顯示比對差額 | 中：約一個批次，需證明舊路徑結果與 main 一致 |

不建議：從 main 逐項移植（見第一節）、或不加限制直接整包上線（路線 B 的情況下會停掉月結）。

## 三、功能分組

### 先上線（兩條路線都包含）

| 功能 | 使用者看到的變化 | 對發薪金額的影響 |
|---|---|---|
| 例假／休息日逐月指定＋雙人核定 | 偏好設定新區塊；管理者新頁「例假／休息日核定」 | 無（只產生日別日曆，供之後計薪用） |
| 補打卡新流程（版本、撤回、更正鏈、雙擊防重送） | 補打卡表單與審核畫面改版 | 無；核准後同樣寫回打卡紀錄 |
| 假單生命週期（撤銷／銷假、核准後更正） | 請假頁多出撤銷與更正 | 無 |
| 出勤異常案件中心＋異常說明 | 管理者新頁「異常待辦」，員工可補說明 | 無 |
| 打卡紀錄修改需勾選「已核實實際工作時間」 | 管理者改打卡多一個確認步驟 | 無 |
| 薪資有效期主檔、離職結算紀錄（僅記錄） | 管理者新頁 | 無；離職結算只記錄、不付款 |
| Tailwind 改為建置（不再用 CDN） | 外觀應相同，需目視驗收 | 無 |

### 先上線但隱藏（程式在、政策未核前沒有作用）

| 功能 | 隱藏原因 |
|---|---|
| 加班事前申請 | 需核定的加班流程政策才會啟用 |
| 補休帳本與結清 | 補休個別同意、期限與原日來源未核 |
| 附件上傳 | 正式儲存與掃描未設定，維持停用 |

### 留在分支（V2 以後）

| 功能 | 原因 |
|---|---|
| 新計薪引擎作為正式金額（正常薪資、加班費、補休折算） | C2b 來源缺口、C3 保費／稅、八月全員對帳都未完成 |
| 系統內月結鎖定與薪資快照（路線 A） | 依賴上一列 |
| 差額採用、rollout 與 rollback 機制（D） | 依賴上一列 |

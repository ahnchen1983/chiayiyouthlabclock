# 上線規劃：讓系統正確算出薪資並作為發薪依據

日期：2026-10-25（同日修正方向）。基準：main `84091c6`（8/5 最後上線）、PR13 `13717ca`、PR14 head。本文件是規劃，尚未合併、部署或寫入任何正式資料。

## 目標

系統本來就該算對。先前薪資在系統外計算，是因為系統算錯，不是設計選擇。**上線條件：系統算出 2026-08 全體人員薪資，逐人與實際發放核對一致（差額都有說明），之後即以系統作為發薪依據。**

> 修正紀錄：本文件初版提出「路線 A 試算模式」，把系統金額標成「不作為發薪依據」並隱藏流程。那是把缺陷當成設計，已撤回（`481a253`）。

## 一、盤點事實

1. **不能從 main 逐項挑功能上線。** 新功能都建在 PR13 新增的共用模組上（monthGuard、attendanceCaseService、payrollPreflight 等，main 都沒有），逐項移植等於重寫。main 自 8/5 後沒有變動，PR13 以現行 main 為基準，整包合併不會衝突。
2. **目前月結被 5 個寫死的缺口擋住**（`payrollPreflight.ts` 的 `PREFLIGHT_GAPS`）。這是待辦清單，不是永久設計：每補完一項就移除一項，全部移除且八月核對一致才能月結。

## 三、建議順序

1. **先把八月能算的算出來**：我把加班費接進正式金額並補跨月週來源，同時你建立八月主檔與政策版本、補登日別。完成後系統能產出八月正常工資＋加班費。
2. **勞健保與扣項**：實作 C3，接上你提供的投保資料，產出實發金額。
3. **八月對帳**：逐人比對系統與實發，差額逐項說明並核定；系統錯的修系統，實發錯的另案處理。
4. **全數一致後**：移除最後的缺口，合併 PR13 上線，九月起以系統作為發薪依據。

非計薪功能（補打卡新流程、銷假、異常案件、例假／休息日指定）隨同一次合併上線。

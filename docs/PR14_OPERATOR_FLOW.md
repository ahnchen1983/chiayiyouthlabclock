# 薪資與出勤操作流程

本指南說明已接線的通用流程，不代表正式資料已完成核定或部署。實際權限、證明、有效期及來源金額必須據實提供；畫面待核資訊不能用預設值排除。

## 未鎖月份

1. 由「薪資有效期主檔」「計薪政策版本」「例假／休息日核定」「投保資料」建立及獨立核定適用來源。未來生效保護保留，不用目前主檔回填歷史。
2. 在「出勤紀錄」「異常待辦」核實實際工作、休息、請假與更正，完成整月掃描及案件結案。來源變更後重新取得當前證據；核實工作來源也供月／三月工時檢查使用。
3. 「工時制度聲明」「出勤判定政策」保存適用制度及真實授權來源。完整跨月來源及有效規則是月結前提。
4. 「其他薪資項目」明示無其他項目，或列出有來源的固定項目。「薪資項目處理」保存分類證據；有界可計算項目再由「薪資項目計算」提出明示處理及獨立核定。不能依名稱推斷免稅、扣款合法性或加班基礎排除。
5. 「給付證據核對」記錄實際支付事件與適用證明。適用的兼職逐次計算再由「給付金額分配」分配既有事件的來源項目，核定後進入共同薪資計算；不能自行拆造付款。
6. 「薪資差額核對」逐項填寫有來源的實際金額及淨額，另一人覆核，零差額再另行記錄採納。非零差額可由「薪資調整」提出、覆核、採納及記錄獨立帳務分錄。
7. 「月薪資對帳」顯示完整名冊及尚缺證據。全部來源、工時、D零差額採納及實際支付對齊後，由兩位非當事管理員提出與覆核當前摘要，再至薪資頁鎖月。來源變更後核定失效；鎖月保留不可變快照，不能解鎖覆寫。

調整分錄不會改寫實際轉帳，也不會把未支付差額變成已支付。若計算義務與實際支付不同，月結仍需正確的支付與逐項核對證據。負調整不代表可自動扣薪或追回款項。

## 已鎖月份

「歷史薪資差額」預設比較原始快照與實際證據，讀取時不按現行主檔重新計算。

如果完整原快照中的契約薪率需更正，使用「歷史薪率修正」明示原版本、期間、薪率及權限來源，核對投保資料保持適用的依據，經獨立覆核及另行採用後，在歷史D中明示選擇該更正版本。目標由伺服器重新計算，不允許直接指定目標淨額。非零已覆核差額接「薪資調整」，選擇未鎖的入帳月份記錄分錄；原薪資、原支付及原鎖月仍保留。

此修正適用於完整原快照的薪率事實；缺失歷史主檔、需重選政策／日別／實際工作、原支付分配重綁、額外項目重分類或補休原工資變動，不在薪率修正表單的有界範圍。系統會列出待核原因，不能據此宣稱所有歷史更正種類已完成。

## 正式採用前尚需決定或提供

- 真實八月資料採獨立系統內歷史證據集或外部唯讀報告，及其保存與採用授權。
- 每人的實際主檔、投保／稅務身份、政策與工時授權、項目六類依據、支付與差異來源。
- 個別補發／追回的依據及實際執行安排。系統記錄對帳分錄，不執行銀行付款或自動追扣。
- 稅額角分、未有確認規則的查詢月底效期或特殊所得／工時情況，只對受影響輸入保持待核。

PR、合併、部署與正式政策啟用是另外的放行步驟；本次開發與合成驗證不執行這些動作。
